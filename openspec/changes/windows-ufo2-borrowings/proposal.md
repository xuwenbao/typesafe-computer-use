## Why

Microsoft 的 UFO2（[论文](https://arxiv.org/html/2504.14603)，[代码](https://github.com/microsoft/UFO)，MIT）是 Windows 上做得最深的桌面代理，其中有三个机制正好补 jev 在 Windows 上的短处：jev 运行时占用维护者正在用的桌面；接管模型每次调用只走一步，而每次推理要几秒到十几秒；UIA 只用了 Invoke 与 Value 两种操作方式，勾选框、下拉框、列表项、滑块仍要靠点坐标或拖动。jev 准备只把 Windows 作为这些能力的目标平台，正好可以照着 UFO2 的做法补上，而不引入它每步都调用大模型的整体架构。

## What Changes

- **画中画模式（隔离会话）**：新增在 Windows 子会话（远程桌面连回本机）里运行 jev 的方式。代理的截图、鼠标、键盘与焦点都只在子会话内，维护者的主桌面不受影响；子会话以同一用户登录，沿用其账号、登录状态与已装软件。主桌面上的一个轻量控制端通过命名管道与子会话内的 jev 通信：下发任务、查看进度、取消、回答 jev 的提问。只支持 Windows 真实机器。
- **接管模型一次给多步**：接管模型的一次回复可以给出最多若干个按顺序执行的动作（上限可配置）。每个动作执行前照常经过现有的全部代码校验，另外还要核对目标项在最新一次读屏中仍然存在、可见、可用；任何一个动作被拒绝、目标项不见了或屏幕没有变化，就停止执行这一批剩下的动作，把已完成的部分写进历史，再请模型重新规划。接管预算按实际执行的动作数计算，而不是按模型调用次数。分类器的一步一决策不变。
- **借 UIA 的更多操作方式**：Windows 适配器新增 Toggle、ExpandCollapse、SelectionItem、ScrollItem、RangeValue 五种操作方式。来自无障碍树的项目被点击时，按"Invoke → Toggle → SelectionItem → ExpandCollapse → 鼠标点击"的顺序选第一种可用的方式；点不在视野里的控件前先用 ScrollItem 把它滚进视野。接管模型新增 `set_value` 动作，通过 RangeValue 或 Value 直接给滑块、数值框赋值。采集控件时记录每个控件是否可用，以及它支持哪些操作方式。分类器的动作集合不变。

不在本次范围内：

- 危险动作的确认（安全门）。现有的直接拒绝规则（退出类快捷键、凭据）不变，"问用户再执行"这一档留到后续变更。
- 通过应用的程序接口（Office COM 等）完成动作，以及从历史运行中提炼经验或可重放的步骤。
- macOS 的隔离运行与 macOS 上的新操作方式；Linux。
- 分类器一次给多步。
- WAA 虚拟机内的隔离会话（WAA 本身已在虚拟机里，与主桌面隔离）。

## Capabilities

### New Capabilities

- `windows-isolated-session`：jev 如何在 Windows 子会话里运行。包括子会话的创建、登录与关闭，jev 进程在子会话内的启动，主桌面控制端与子会话之间的命名管道协议（任务、进度、取消、提问与回答），对系统版本与设置的要求及不满足时的报错，以及截图与输入只作用于子会话的保证。
- `driver-multi-action`：接管模型一次回复多个动作时的规则。包括一批动作的上限、逐个执行前的校验（现有校验加上目标项仍存在、可见、可用）、提前停止的条件、已执行与未执行动作在历史和运行记录中的写法、接管预算的计法，以及模型提示与回复结构的变化。
- `windows-uia-patterns`：Windows 上通过 UIA 操作方式执行动作的规则。包括五种新操作方式各自适用的控件、点击时的选择顺序与回退到鼠标的条件、ScrollItem 的使用时机、`set_value` 动作的校验与读回、采集控件时记录的可用状态与操作方式，以及真实机器与 WAA 虚拟机两条执行路径一致。

### Modified Capabilities

- `waa-uia-tree`：要求"角色与真实 Windows 机器一致"扩展为节点还要带上是否可用与支持的操作方式，且与真实 Windows 机器来自同一份定义；新增要求：在 WAA 虚拟机里执行 UIA 操作方式时同样通过 `/execute` 运行，并与取树一样不与其他动作重叠。

## Impact

- **代码**：
  - `yuanji_computer_use/windows.py`：新的 UIA 操作方式、可用状态与操作方式的采集、子会话内运行所需的会话检测。
  - `yuanji_computer_use/driver.py`、`writer.py`（`DRIVE_ACTIONS`、`DRIVE_SYSTEM`、`DriveStep`、`compose_drive_step`）：一次多步与 `set_value`。
  - `config.py`：一批动作的上限。
  - 新增隔离会话模块（主桌面控制端与子会话内的服务端），以及对应的命令行入口；子会话内的提问复用现有的 `ctx.ask`，经命名管道转给控制端。
  - `yuanji_computer_use/waa/`：虚拟机内的取树脚本输出新字段；UIA 操作方式在虚拟机里的执行。
- **依赖**：Windows 上可能需要 `pywin32` 中 WTS 与命名管道的接口（已是 Windows 依赖的一部分则不新增）。macOS 依赖不变。
- **环境**：隔离会话需要 Windows 专业版、企业版或教育版并开启远程桌面；具体前提（子会话开关、组策略）在设计中确定，不满足时给出明确的报错，而不是退回到在主桌面运行。
- **测试**：新增三项能力的离线测试。`tests/conftest.py` 的机器守护 SHALL 在同一变更中加入所有新的会触及机器的调用：UIA 新操作方式、子会话的创建与连接、命名管道。
- **规则与文档**：`AGENTS.md` 写明启动隔离会话与在会话里运行 jev 同样需要每次批准（它仍是"在这台机器上运行项目"）；更新 `docs/how-a-step-works.md`（动作集合、接管）、`docs/writer-endpoints.md`（新配置项）、`README.md` 与 `CONTRIBUTING.md`；新增隔离会话的使用文档。
- **可比性**：接管一次多步会改变 WAA 上的步数与模型调用次数，`run.json` 需分别记录动作数与调用次数，与此前的结果比较时以动作数为准。
- **平台**：隔离会话与 UIA 操作方式只在 Windows 上。接管一次多步写在与平台无关的接管模块里，macOS 上也会生效；macOS 的无障碍树不提供"可用"状态时，一批动作的核对只看目标项是否仍存在、可见。
- **不受影响**：浏览器路径（`browser/`）、沙盒（`scripts/sandbox`）、macOS 适配器本身、分类器的动作执行。
