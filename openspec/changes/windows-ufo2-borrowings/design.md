## Context

jev 的每一步都在本机前台操作：`windows.py` 用 `ImageGrab` 截屏、用 `SendInput` 发输入、用 UI Automation 读前台窗口。接管在 `driver.py` 的 `take_over` 里，一次模型调用只得到一个 `DriveStep`，执行前在 `act` 里核对；`config.py` 的 `driver_steps` 按"一步一次调用"来计。Windows 上对控件的操作只有 `ax_press`（Invoke，或有名字的 Legacy 默认动作）和 `ax_set_value`（Value）。WAA 的路径不同：`waa/walk_vm.py` 在虚拟机里取树，`waa/desktop.py` 把动作攒成 pyautogui 代码，要等下一次观测才真正执行。

UFO2 论文里对应的三个机制是：用远程桌面连回本机开一个子会话来隔离运行；一次推理给出一批动作，执行前用 UIA 核对控件还在；以及 Toggle、ExpandCollapse、SelectionItem、ScrollItem、RangeValue 这些操作方式。UFO2 仓库（MIT）里没有画中画的实现，隔离会话按微软的子会话接口设计。

## Goals / Non-Goals

**Goals:**

- Windows 真实机器上，jev 可以在子会话里跑完一次任务，截图和输入只落在子会话，主桌面仍可使用。
- 接管模型一次回复可以带多个动作；每个动作执行前都核对，任何一个不成立就停掉这一批剩下的，再请模型规划。
- 来自无障碍树的点击能用上 UIA 的操作方式，真实机器和 WAA 虚拟机用同一套选择顺序。
- 分类器的动作集合、一步一决策、以及现有的直接拒绝规则保持不变。

**Non-Goals:**

- 安全门、Office COM 接口、从历史运行提炼经验、分类器一次给多步。
- macOS 的隔离会话，以及给 macOS 增加新的操作方式。
- 在 WAA 虚拟机里再开子会话。
- 把 UFO2 的主机代理、每个应用一个代理的结构搬进来。

## Decisions

### 1. 隔离会话用 Windows 的子会话，失败就停

子会话是挂在当前登录上的一个本地远程桌面会话（[Child Sessions](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions)）。父会话先调用 `WTSEnableChildSessions(TRUE)`，再用远程桌面 ActiveX 控件，在连接前把 `IMsRdpExtendedSettings` 的 `ConnectToChildSession` 设为真，然后 `Connect()`。同一用户自动登录，不另要密码；智能卡登录除外，那种情况控件会要求凭据。

选它是因为它和主桌面分开输入队列与焦点，又沿用同一用户的账号、登录状态和已装软件。虚拟机或沙盒做不到这一点。

前提不满足就报错退出，不退回到主桌面运行。前提是：

- Windows 专业版、企业版或教育版。家庭版没有可用的远程桌面主机，不支持。
- 本机能用远程桌面连 `localhost`。证书不被信任、远程桌面被组策略关掉，都算前提不满足。
- 不是用智能卡登录的。智能卡登录时子会话不会自动登录，第一版不做。
- 同一台机器同时只能有一个子会话。已有一个时，报出它在运行，而不是再开一个。

已知限制，写进使用文档，不在代码里绕过：剪贴板与主会话共用；同一个 Office 应用不能两边同时开着；开机自启动的程序会在子会话里再开一份；子会话开着时不要重启机器。

**控制端与会话内进程**

新增 `yuanji_computer_use/windows_session.py`，只有执行对应命令时才导入，和 `windows.py` 一样不进入 macOS 的导入路径。命令行入口是 `clicker session`。

- 父会话里的控制端做三件事：启用子会话、开一个窗口把远程桌面控件嵌进去（这就是画中画）、创建命名管道。它不导入平台适配器，不发任何鼠标键盘输入。
- 子会话里启动 jev。做法是：连接成功后枚举会话，找到子会话里的 `explorer.exe`，复制它的令牌，用 `CreateProcessAsUser` 启动 jev。目标进程属于同一用户，不需要管理员。jev 的环境变量带上 `JEV_SESSION=1` 和管道名。
- jev 启动时如果发现 `JEV_SESSION=1` 但自己仍在控制台会话里，直接拒绝运行。这是防止截图和输入落到主桌面的最后一道检查。

**如果跨会话打开进程被系统拒绝**，改用第二条路：连接时把控件的启动程序设为 jev 的启动器，由启动器在子会话里拉起资源管理器和 jev。两条路都只在子会话里产生进程。先实现第一条，在一台 Windows 专业版机器上验证；验证不了就换第二条，不保留两条并存。

**命名管道**

管道由控制端创建，只允许当前用户访问，并拒绝远程客户端。消息是一行一个 JSON 对象：

| `type` | 方向 | 内容 |
|---|---|---|
| `task` | 父 → 子 | 目标与运行参数，子会话里的 jev 收到后开始跑 |
| `log` | 子 → 父 | 一行运行日志，控制端原样打印 |
| `progress` | 子 → 父 | 已用动作数与预算 |
| `question` | 子 → 父 | 写手的提问。子会话里的 `ctx.ask` 改成把问题写进管道并等待 |
| `answer` | 父 → 子 | 用户在控制端输入的回答 |
| `cancel` | 父 → 子 | 用户取消。子会话里的 `check_abort` 看到它就走现有的中止路径 |
| `done` | 子 → 父 | 结局与运行目录的位置 |

控制端没有单独的图形界面：远程桌面窗口显示子会话的桌面，日志和提问走控制端的标准输入输出。

macOS 上执行 `clicker session` 直接报"只支持 Windows"。

### 2. 接管一次回复一批动作，逐个核对后执行

一次模型调用的回复从单个动作改成一批。`driver_steps` 改成按实际执行的动作计数，`config.py` 里"每步一次模型调用"的说明一并改掉。新增 `driver_batch`，默认 3，最小 1。设为 1 时，行为与现在一次一个动作相同。

回复结构是一个 `reason` 加一个有序列表 `actions`，列表里每个动作的字段与现在的 `DriveStep` 相同。`done` 和 `give_up` 只能是列表的最后一项。列表长度超过 `driver_batch`、为空、或动作名字不在名单里，整批视为读不成动作，沿用现在连续两次就停下的规则。

**一个批次怎么执行**

按顺序执行。每个动作先走 `act` 里现有的全部校验，再加一道新鲜度核对：目标项来自无障碍树时，重新问适配器这个元素是否还在、是否可见、是否可用。三个里有一个不成立，就拒绝这个动作。然后：

- 动作被拒绝、目标项核对失败、或动作是 `done` / `give_up`：这一批剩下的不再执行。
- 动作执行后截一张图，用现有的分块比较看屏幕有没有变化。等待、输入、复制、剪切不参与这个判断；其余动作屏幕没变化，就停掉这一批剩下的。这一张图只用于比较，不跑 OCR，也不跑图标检测。
- 重复与空转的计数仍由现有规则处理，一批做到一半也可以因此结束整次接管。

没有执行的动作不写进历史。历史里追加一行 `driver: stopped the rest of the batch: ...`，说明停在哪个动作、为什么，下一步模型能读到。每个已执行的动作仍是一行 `driver:`，与现在一致。

预算只数实际执行了的动作，包括被拒绝的。`done` 和 `give_up` 不计数，它们结束接管。一次调用写一个 `step-NNN-driver.json`，里面是整批动作和每个动作的结果；`NNN` 仍按动作序号递增，文件里另记这次调用的序号，这样动作数和调用次数都能从运行目录里数出来。

**新鲜度核对放在适配器后面**

`Desktop` 增加一个方法，给定元素句柄，返回它是否还在、是否可见、是否可用；问不到就返回空。`windows.py` 用 UIA 的 `IsEnabled` 和 `IsOffscreen` 回答。`macos.py` 只回答是否还在、是否可见，不报告可用，核对时就跳过"可用"这一项。

WAA 上动作是攒着的，要等下一次观测才执行，所以一批动作不能闭着眼睛全发出去。`WAADesktop` 在回答这个方法时，先把已经攒下的输入作为一个步骤交给虚拟机，拿回新的观测和树，再按树里的记录回答。因此在 WAA 上，一次多步省下的是模型调用，不是虚拟机的步骤。省下的调用仍然值得：UFO2 的测量里，一步的时间大部分花在模型推理上。

**提示词**

`DRIVE_SYSTEM` 从"每次回复一个动作"改为"每次最多 `driver_batch` 个动作，只列出不需要看到中间结果就能确定的动作"。后一个动作所依赖的控件必须是这一屏上已经标了号、且来自无障碍树的项。模型把 `done` 或 `give_up` 放在列表最后来结束。

**没有无障碍树的项**

OCR 或图标项没有元素句柄，无法做新鲜度核对。这类动作只允许出现在一批的第一个；排在后面就拒绝并停掉剩下的。这样一批里真正连续执行的动作，都有操作系统级别的核对。

### 3. UIA 操作方式：先沿用现在的按下，再用新方式

新增的操作方式不改变"按下"的含义。`ax_press` 现在先 Invoke，没有再执行有名字的 Legacy 默认动作，这个顺序保留。新方式只在两者都没有时才用，顺序是：

1. Invoke（现有）
2. 有名字的 Legacy 默认动作（现有）
3. Toggle
4. SelectionItem 的 Select
5. ExpandCollapse：折叠着就展开，展开着就折叠
6. 鼠标点击（现有的回退）

把 SelectionItem 放在默认动作之后，是为了资源管理器里的列表项维持现在的行为：它们没有 Invoke，但有名为"打开"的默认动作。如果先走 Select，单击就从"打开"变成"选中"。复选框通常带着名为"选中"的默认动作，仍走第 2 步，结果与 Toggle 相同。

双击、右键、带修饰键的点击不走这套顺序，它们表达的是鼠标手势，继续用 `click_at`。

**ScrollItem**

`press_offscreen` 和 `focus_offscreen` 在操作之前，如果控件支持 ScrollItem，先 `ScrollIntoView`。屏幕上看得见的点击不滚动，避免把页面挪走。WAA 的 `ax_focus` 已经会先滚动，真实机器的 `windows.py` 补上同样的一步。

**可用状态**

采集控件时读 `IsEnabled`。明确读到不可用的控件仍出现在列表里，让模型看得到，但对它的操作（包括鼠标回退）直接拒绝，历史里写明是因为不可用。读不到这个属性时维持今天的行为，不凭空拒绝。

**`set_value` 只给接管模型**

`DRIVE_ACTIONS` 增加 `set_value`，用 `item` 和 `text` 两个字段。目标项支持 RangeValue 时，把 `text` 解析成数值，核对它落在该控件的最小值和最大值之间，设置后读回；支持 Value 时走现有的 `ax_set_value` 并读回。两者都不支持、像凭据、或只读，就拒绝。分类器的动作集合不变，文本仍由 `type_text` 处理。

**操作方式要进到模型看到的项目里**

`AxNode` 增加 `enabled` 和 `patterns` 两个带默认值的字段，现有的构造处不用改。`walk_actionable` 从适配器的 `actions()` 里收下这些操作方式的名字。`to_ax_items` 把它们带到 `Item` 上，`compose_drive_step` 的 `screen_items` 里多一个 `controls` 字段，模型才知道哪一项可以 `set_value`、哪一项是开关。

**真实机器与 WAA 共用定义**

操作方式的标识和 UIA 的 pattern id 写在 `uia_roles.py` 旁边的一份无 Windows 依赖的定义里，`windows.py` 和 `waa/walk_vm.py` 都引用它。`walk_vm.py` 在节点上增加 `enabled` 和 `patterns`。`WAADesktop` 按 `ax_focus` 现有的方式，在虚拟机里执行这些操作：按名称和控件类型找回元素，调用对应的 pattern，失败就返回假，让调用方走下一个方式或回退到鼠标。

**适配器的接口**

`Desktop` 增加一个方法 `ax_operate(ref, operation, value=None)`，`operation` 取 `toggle`、`select`、`expand_toggle`、`scroll_into_view`、`set_range` 之一。做成一个方法而不是五个，是因为每个适配器和测试里的替身都要实现 `Desktop`。`macos.py` 对全部返回假，点击就回退到鼠标。`ax_press` 保持原样。

选择顺序写在 `actions.py` 的 `click_item` 里，不写在适配器里，这样两条路径的顺序不会各写一份。

### 4. 测试与机器守护

新增的会触及机器的调用都进 `tests/conftest.py` 的守护，与实现同一批提交：UIA 的新操作方式、`ax_operate`、子会话的启用与连接、跨会话启动进程、命名管道的创建。测试用替身适配器验证选择顺序、一批动作的提前停止、预算计数和管道消息的解析，不真的开子会话。

## Risks / Trade-offs

- [子会话的进程启动方式没有在本机验证过] → 决策 1 先走复制令牌，验证失败就换启动程序，两条都不退回主桌面。第一版不支持家庭版、智能卡登录、以及连不上 `localhost` 的机器。
- [子会话与主会话共用剪贴板，Office 不能两边同时开] → 写进使用文档。jev 在子会话里操作 Office 时，主会话里的同一应用需要先关掉，文档里说明。
- [一批动作里的截图比较会漏掉细小变化] → 沿用现有的分块比较阈值，漏判的后果只是提前结束这一批、多一次模型调用，不会多执行动作。
- [WAA 上一次多步并不减少虚拟机步骤] → 运行记录分开记动作数和模型调用次数。与旧结果比较步数时以动作数为准，比较开销时以调用次数为准。
- [Toggle 会翻转状态，模型如果想要的是某一个确定状态，可能翻错] → 项目信息里带上当前状态（已勾选、已展开、当前值），提示词要求模型按当前状态决定。需要指定数值的控件走 `set_value`，不走点击。
- [明确不可用的控件连鼠标回退也拒绝，可能挡住以前靠鼠标点中的控件] → 只在确实读到"不可用"时拒绝；读不到属性时保持现状。

## Migration Plan

- 没有数据要迁移。`driver_batch` 的默认值是 3，不设环境变量就是新行为；设为 1 可以回到一次一个动作。
- 接管的运行记录多了调用序号。旧的 `step-NNN-driver.json` 仍是一个动作一份，读取结果的代码对缺少调用序号的旧文件按"一次一个动作"处理。
- 文档与 `AGENTS.md` 在同一批改动里更新：`clicker session` 属于"在这台机器上运行项目"，每次都要单独批准。
- 回退就是不使用 `clicker session`，并把 `driver_batch` 设为 1。UIA 新操作方式没有开关：它只在现有按下方式不存在时才生效，回退意味着恢复 `click_item` 里的旧顺序。

## Open Questions

- 复制子会话里 `explorer.exe` 的令牌来启动进程，是否会被跨会话的进程隔离拒绝。需要在一台 Windows 专业版机器上验证，结果决定走决策 1 的哪一条路。
- `driver_batch` 默认取 3。等有一批 WAA 结果后，再看成功率是否持平、调用次数是否下降，决定要不要调整默认值。
